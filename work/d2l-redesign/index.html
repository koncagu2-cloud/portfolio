This portfolio walkthrough presents original screens in task order; it does not establish a fully connected prototype. Screen content is illustrative.

Quick read / Design rationale

Three decisions to explore.

  1. Keep assignment context visible ↓

    Missing location cues prompted a named assignment and active navigation. Consistency across courses still needs evaluation.

  2. Review the file before Submit ↓

    The selected filename and removal control make the pre-submit choice inspectable. Replacement after submission remains unresolved.

  3. Separate criteria from scores ↓

    Distinct rubric headers respond to ambiguity between cells. Easier authoring is an intended benefit, not a measured result.

01 / Understand requirements

Start with the requirements.

User task. Understand what the assignment asks before choosing a file.

Design response. The named assignment groups its directions, due date, points, submission type, and status beneath the course navigation.

This screen shows an already-open assignment, rather than the process of finding it.

Show design annotations
  1. Keep location visible. Assignments is underlined in the navigation, with the assignment named directly below.
  2. Bring requirements together. The summary and directions appear before the Add File action. Dates and coursework are illustrative.

02 / Review selected file

Check the file before Submit.

User task. Check which file is selected before committing to submission.

Design response. The selected-file concept names the chosen PDF and provides removal, Add File, Cancel, and Submit controls.

Removal is shown before Submit. The post-submission replacement question is discussed in Reflection.

Show design annotations
  1. Name the chosen file. The filename identifies the current selection rather than showing only a generic upload state.
  2. Allow reconsideration. The X represents pre-submit removal; it is not evidence of replacing an already-submitted file.

03 / Check submission record

Check the submission record.

User task. Inspect the proposed record of submitted coursework.

Design response. The separate history screen presents the filename, an illustrative submission date, and Submitted status.

History is a separate source state; the original prototype does not establish this as the destination after confirmation.

Show design annotations
  1. Make the displayed status explicit. The assignment summary reads Submitted in this state. It is interface content, not a live submission result.
  2. Provide a record to inspect. The history entry includes a file and submission date. Opening the pictured file is not part of this portfolio walkthrough.

Requirements connect both sides of coursework.

Students interpret the requirements and grading criteria instructors prepare. The instructor concept groups assignment setup and gives criteria and scores separate labels in the rubric maker.

06 / Reflection

What the proposal makes visible—and what to evaluate next.

The result is a set of student and instructor interface proposals, supported by heuristic notes, task flows, and sketches—not a deployed submission system.

The unresolved confirmation state makes a specific lesson visible: a success message and the underlying assignment status must tell the same story. A polished screen alone does not establish a coherent submission journey.

Submission recovery

The original screens show removal before Submit. The later demo keeps the existing record until a replacement is confirmed. Can a student identify the file for grading after cancelling a replacement?

Status consistency

The confirmation overlay retains “Not Submitted” underneath. The revised demo derives the receipt and current file from the same record. Whether students understand it remains untested. Inspect the original confirmation state.

Complete the connections

An assignment-list link is missing, and history sits on a separate path. Connect and evaluate the full journey, including keyboard access and screen-reader feedback.

Proposed next steps, not completed validation.
